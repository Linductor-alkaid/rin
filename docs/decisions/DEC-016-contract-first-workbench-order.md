# DEC-016：M4/M5 交错实施——视图契约与假引擎先行

> 状态：Accepted
> 日期：2026-09-24
> 负责人：Linductor-alkaid
> 冻结里程碑：M5（集成验收时复核）
> 替代/被替代：无

## 背景与问题

M5（工作台 UI）是当前设计不确定性最高的部分：节点编辑器交互、参数面板与性能
展示需要多轮试错。原计划按 M4（节点库与工作流引擎）→ M5 的顺序推进，UI 调试与
引擎调试耦合：每轮 UI 迭代都要背负真实 CV 执行来定位问题，反馈周期长；且在
M5-01（信息架构调研）冻结前，引擎-UI 集成设计无法启动。

## 决策

采用"契约 + 假实现先行"的交错顺序：

1. 先在 Core 冻结工作流视图契约（`M4-09`）：工作流图模型、类型化节点参数、
   逐节点与端到端统计 schema、运行控制命令与事件语义，作为 UI 与引擎之间的
   唯一契约面。
2. M5 提供契约假引擎（`M5-08`）：合成图与预置中间结果、仿真统计，经 Executor
   有限任务与 `executor::comm` 通道驱动，复刻 `EXEC-07` 的有界在飞、显式丢弃、
   提交拒绝、取消与关闭语义，覆盖失败路径。
3. M5 骨架（导航壳、节点画布、参数/性能面板、运行控制 UI）对假引擎先行开发
   调试（`M5-02`..`M5-05`）。
4. M4 按同一契约实现真引擎与算子（`M4-03`..`M4-08`），在 `M5-06` 完成假换真
   集成；M5 的完成点仍在 M4 之后。

## 备选方案

- 维持 M4 → M5 原序（引擎先行、UI 后置）：被否——UI 试错期与引擎调试耦合，
  每轮交互迭代都需要真实引擎参与，定位成本高。
- UI 直接对真引擎开发、契约后置：被否——契约将漂移进 UI 代码，违反
  "先契约后实现、先假实现后真实依赖"的总计划拆分原则（工程规范 §3.1）。

## 影响与风险

- 假引擎与真引擎语义不一致会使 UI 调试结论失真：以两实现共用的契约测试约束；
  假引擎必须覆盖提交拒绝、节点失败、取消、关闭路径，不得只实现正常路径。
- 性能面板对假统计调通不代表性能达标：性能结论以真引擎实测为准（`M4-08`、
  `M5-07`），禁止以假引擎统计宣称性能。
- 里程碑依赖调整：M5 骨架仅依赖 M3 与 `M4-09` 契约；M5 完成依赖 M4。
- 视图契约按公开契约对待：变更须同步设计文档与本记录（工程规范 §8）。

## 验证方式

- `M4-09` 契约头文件的类型与校验单测。
- `M5-08` 假引擎与 `M4-07` 真引擎共用契约测试套件。
- `M5-06` 假换真集成回归（含 `onShutdown` 关闭顺序）。
- `M5-07` 真机端到端验收；性能数字以真引擎实测记录为准。
